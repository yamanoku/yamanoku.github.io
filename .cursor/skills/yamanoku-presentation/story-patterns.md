# ストーリー型

## 全型に共通する骨格

1. **フック**: 会場や日常への問いかけで始める（「皆さん、今日はどうやってここまで来ましたか？」）。または「なぜ今この話か」、前回登壇からの接続
2. **自己紹介**: フックの直後に短く置く。「やまのくと申します」、会社員／一児の父／千葉在住、関わるコミュニティ。技術トークは短く、エッセイ型は長め。Slidev では終盤にプロフィールを置くこともある
3. **前提合わせ**: 用語の定義や誤解の解消（「本題に入る前に、前提を揃えたいと思います」）。スコープと対象聴衆を明示する
4. **問題の提示**: 定義の曖昧さ、歴史の帰結、現場のエピソード、「残念な」実装例
5. **根拠で解く**: 仕様・APG・WCAG・MDN・論文の引用、コード、表、タイムライン、デモ動画（before → after）、数字
6. **展望**: 今後の仕様・技術動向
7. **行動の呼びかけ**: 小さく具体的な一歩（「まずはやってみて、残してみよう」「調べてみるとよいかもしれません」）。「〜していきましょう」「共に作っていきましょう」と連帯で締める
8. **締め**: タイトル回収／一句／「以上で発表を終わります。ご清聴いただきありがとうございました。」
9. **謝辞**（任意）・**参考文献**

一貫した価値観: ネイティブ要素優先（「Use button, not div」「NO ARIA is better than BAD ARIA」）、「0か1かの話ではない」、「ウェブは元々アクセシブル」、手段より意図に立ち返る。技術を否定せずバランスを取る（「使ってはいけないと言いたいわけではありません」）。

## 教示型（デフォルト）

```
## はじめに            フック + 自己紹介 + 今日の焦点
## 〇〇とは            定義・前提合わせ
## 〇〇の変化／歴史    なぜ問題が生まれたか
## これは〇〇？        現場エピソードで問題を具体化
## 「残念な」〇〇      悪い例を複数提示し、疑問を残す
## 仕様から見る〇〇    1つ目を一次情報で解く（以降、悪い例の数だけ繰り返す）
## おわりに            責任・普遍性・タイトル回収・呼びかけ
## 参考文献
```

例: burikaigi-2026（悪い例3つを提示し、HTML仕様 → APG → WCAG/ARIA の順に解く）、vuefes-japan-2025、frontendo-2024、vuefes 2022/2023。

## 経緯型

```
## 発表概要           読者向けの要約
## スライド内容        口語の通し原稿
  〇〇とは → 何が欠けていたか → 仕組み → タイムライン → まとめ
## 参考情報
```

例: tskaigi-2026。Slidev は `layout: section` で大きな区切りを入れる。

## 対比型

イベントのテーマ語を軸に、対になる2つの概念で構成する。

```
## 自己紹介           人物 + コミュニティ → 題材への橋渡し
## 〇〇について        題材紹介・由来・データ
## 〇〇と「かわるもの」     変化を軸ごとに
## 〇〇と「かわらないもの」 対になる不変の原則
## ファーストステップ       一般化して呼びかけ
## 最後に一句              ユーモアで締め
```

例: dai-kichijojipm-2026（`duration: 15min`）。

## 寓話型

タイトルと全体をネタの物語（なろう系など）に仕立て、場面ごとの画像とナレーションで技術の変遷を語る。転生 → 栄華 → 没落 → 救済 → メタなオチ。途中に「ーーーすみません、ここで緊急ニュース」のような差し込みを入れる。物語部分の一人称は「俺」。

例: tskaigi-2025。

## エッセイ型（flat）

見出しは `## スピーカーノート` だけにし、全文を口語で書く。挨拶 → 自己紹介 → 人生と題材への問い → 年表的な回想 → 信念 → モヤモヤ → 出会い・引用 → コミュニティへの感謝 → 御礼。

例: dai-funabashidev-2026。

## シリーズ物（同じカンファレンスに連続登壇）

冒頭で前年の登壇に触れ、「前回は〇〇、今回は〇〇に焦点を当てます」とつなぐ（vuefes 2023・2025）。Slidev では過去登壇のスライドを2枚並べて見せる。
